# Windows and printer acceptance checks

Expensive-item acceptance: select a PN listed in column A of **expensive components**, including its first row. Verify the ` - EXPENSIVE ITEM💰` UI suffix, two-label indication, and a dry-run file with two formats. Physically validate one normal and one L3 expensive label per click, with the same selected PN/MPN and unchanged warning graphic; ordinary parts should still yield only one label. Check alternate MPNs for a listed PN, add/remove a PN and refresh, and repeat offline with a valid combined cache. If either tab is unavailable, the prior expensive flags must remain. Record the expensive template hash after its hardware checks pass.

Automated tests establish data/rendering/update behavior. These checks need Windows interaction or the actual printer; do not mark them complete merely because a spool job was accepted.

1. Start with `Run.cmd --sample`. Use Tab, Shift+Tab, arrows, Enter, Escape and mouse selection. Verify duplicate PN suggestions show different MPNs. Editing the search must clear the prior selection; quantity starts blank on each fresh launch.
2. Start against the live sheet; verify the initial download and manual **Update database**. Enter a date and quantity, wait five minutes and confirm a refresh without losing inputs. Suspend/resume Windows past the due time and confirm an immediate refresh. In a test sheet, remove the selected exact pairing and refresh: selection and printing must clear.
3. After a successful sync, disconnect networking and restart. Search the cached data; verify last-sync time, cache age, failure status and the next refresh countdown. Use a separate empty `--data-dir` offline and confirm that an initial successful download is required. Restore networking and refresh.
4. Resize the window and move it between monitors at 100%, 150% and 200% scaling. Confirm readable text, accessible inputs, scrolling if needed and usable keyboard navigation. Close/reopen and confirm placement/preferences persist.
5. Select a Windows queue, close, remove/rename it and restart. Verify the missing-queue message and no automatic switch. With several queues, confirm every submission uses the explicitly selected queue.
6. Confirm actual Zebra model, DPI, connection, driver/queue, Zebra software edition, media/ribbon, tracking, speed and darkness. The geometry is 354 × 591 **dots**. Review [template notes](../templates/README.md), generate a dry run and inspect its commands.
7. Under controlled hardware validation, use the supplied layout to print a single sticker, check all text/rotation/fixed captions and scan both Code 128 barcodes. Verify exact PN spelling (including any hyphen and leading zeros), leading-zero date MMYY, and one sticker regardless of component quantity. Test the widest supported PN, wide letter text, longest supported MPN and maximum intended quantity. Check quiet zones and reliable scanning on actual material.
8. Record the tested template hash and hardware configuration before enabling production. Verify the primary button stays disabled for unsupported inputs/unvalidated configurations and during submission. Check a successful RAW spool submission and an unavailable queue. For an interrupted/uncertain job, verify there is no automatic retry and follow the operator instruction to inspect the queue/printer.
9. On a fresh test Windows account without .NET 10, extract the setup bundle and run Install.cmd. Check runtime consent, cancellation, download errors, per-user runtime installation, shortcuts and first startup. Also test an existing supported system runtime and offline initial installation with/without a runtime already installed.
10. Test a stable tagged release in a controlled repository. Verify HTTPS checksum/package rejection, offline/rate-limited fallback, semantic version exclusion, one concurrent launcher, startup-ready promotion, crashed-child fallback, and stalled-child close/retry. A new runtime-major package must retain the old working app and request a full installer.
11. While a print is pending, launch the shortcut again: it should activate the operator window without replacing files or interrupting the job. Verify the 30-minute software-update notice and deliberate close/relaunch installation are independent of the five-minute data refresh.

Code signing, actual printer output, barcode scans, multiple-monitor DPI behavior, Windows sleep/resume and real GitHub Release rollout require their own acceptance evidence.
